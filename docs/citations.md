# Citations Pipeline — Best Practices

This document describes how citations flow from a single source of truth to
the PDF, CITATION.cff, and .zenodo.json, and the conventions for adding new
references. It applies to every paper repository in this family
(01-hilbert-polya, 02-odd-zeta, 03-crystalline-worldsheet, 04-mersenne-cr,
05-granularity); the pipeline scripts are byte-identical across them.

## 1. Single source of truth

`citation.csl.json` (a CSL JSON array) is the ONLY place where citation
metadata is edited.

Derived files — never edit by hand, always regenerated by the build:

| File | Produced by | Purpose |
|---|---|---|
| `src/bibliography.bib` | `scripts/tasks/citation.ts` (`data.format('biblatex')`) | BibLaTeX database consumed by biber |
| `CITATION.cff` | `scripts/tasks/citation.ts` (CSL→CFF mapping via citation-js) | Software/dataset citation metadata |
| `.zenodo.json` | `scripts/tasks/citation.ts` (from CITATION.cff) | Zenodo deposit metadata |
| `build/document-vX.Y.Z.pdf` | `scripts/tasks/compile.ts` | The compiled paper |

Editing any derived file by hand is a data-loss bug: the next build silently
overwrites it. The full chain table — which file is the source of which, and
why a title change belongs in `package.json` rather than in the CFF — is
[`architecture.md` §Sources of truth](architecture.md#sources-of-truth).

## 2. The build, end to end

A single command produces everything:

```bash
pnpm run build
```

Order of operations (`scripts/build.ts`):

1. `cleanupOldVersions` — clears `build/`.
2. `syncCitationMetadata` — reads `citation.csl.json`, writes
   `src/bibliography.bib` (BibLaTeX, keys renamed to the CSL `id`s), updates
   `CITATION.cff` and `.zenodo.json`.
3. `compilePDF` — `latexmk -pdf` inside Docker (`kjarosh/latex:2024.4-full`),
   `SOURCE_DATE_EPOCH` pinned to the last commit; biber runs automatically
   through latexmk's `bcf → bbl` rule.
4. `generateChecksums` — `checksums.txt`.

There are no manual steps. If the PDF is stale or the bibliography is
missing, fix the input (`citation.csl.json`, `main.tex`) and rebuild — never
patch intermediate artifacts.

## 3. LaTeX contract (`main.tex`)

The preamble must match the family standard:

```latex
\usepackage{xcolor}\definecolor{linkred}{rgb}{0.78,0.08,0.12}
\usepackage[backend=biber,style=numeric,sorting=nyt,giveninits=true,doi=true,url=true,isbn=false]{biblatex}
\addbibresource{src/bibliography.bib}
\AtEveryBibitem{\iffieldundef{doi}{}{\clearfield{url}}}
\usepackage{hyperref}
\hypersetup{colorlinks=true,urlcolor=blue,linkcolor=linkred,citecolor=blue}
```

The body must NOT contain a manual `thebibliography`. The bibliography is
printed from the database:

```latex
\nocite{SomeKey}      % only for entries that must be listed but are never \cite'd
\printbibliography
```

Every `\cite{key}` key must exist as an `id` in `citation.csl.json`; biber
fails the build otherwise.

## 4. Adding a citation — checklist

1. Verify the metadata against authoritative sources first (Crossref REST
   API preferred; then OpenAlex, publisher pages, arXiv, zbMATH). Example
   batched verification:
   `https://api.crossref.org/works?query.bibliographic=...&rows=3&select=DOI,title,author,issued,page,volume,issue,container-title`
2. Append one CSL JSON object to `citation.csl.json`, keeping the array
   order stable (existing ids first, new entries appended).
3. Fields that apply to the type — omit, never null-pad:
   - `type`: `book`, `article-journal`, `posted-content` (preprint), …
   - `author`: array of `{"given": "...", "family": "..."}` objects.
   - `container-title`, `volume`, `issue`, `page`, `publisher`, `DOI`, `URL`.
   - `issued`: `{"date-parts": [[year]]}` — the PUBLICATION year, not the
     preprint year (the most common defect; arXiv year ≠ journal year).
   - `note`: series names (GTM 42, …) or scholarly remarks only.
4. `\cite{the-new-id}` in the text (or `\nocite` it deliberately).
5. `pnpm run build` and check the rendered entry in the PDF.

## 5. Data hygiene rules (lessons encoded)

- **Root title carries full Unicode**: `package.json.description` holds the
   paper title verbatim (special math characters such as 𝔽₁, μ₆, φ); every
   build copies it into `CITATION.cff` and the Zenodo title unmodified.
   Never ASCII-fold it (`F1`, `mu6`) — that degradation propagates to the
   deposition on every rebuild. The sanitizer applies only to Unicode
   superscripts (→ `<sup>`), never to math alphabetics or subscripts.
- **Author lists are structured.** Each author is one `given`/`family`
  object. A comma-joined blob ("A. X, B. Y, C. Z") makes biber abort with
  `Name "..." has too many commas` and kills the whole bibliography.
- **DOI without prefix**: `10.xxxx/yyy`, never `doi:10.xxxx/yyy`.
- **Do not force DOIs** that do not exist: most pre-1990 works and many
  classic books have none. Never use a review's DOI for the reviewed book,
  and never list series editors as book authors.
- **Preserve the published orthography** of titles (original spellings,
  Unicode names such as Özaydin, Pär); do not "modernise" them.
- **Name style inside `given`**: full given names preferred in stored CSL
  data (better Zenodo/CFF metadata); the render initials them uniformly via
  `giveninits=true`. Long author lists abbreviate to "et al." by design.
- **DOI and URL**: both are stored in CSL/CFF/Zenodo metadata. In the
  rendered PDF the family hook
  `\AtEveryBibitem{\iffieldundef{doi}{}{\clearfield{url}}}` suppresses the
  URL whenever the entry has a DOI (no `doi.org` duplication); entries
  without a DOI keep their URL (retrieved-from sources).
- **Sorting and name style**: references sort alphabetically (`sorting=nyt`,
  the AMS convention for `amsart`) and render with initials
  (`giveninits=true`) regardless of the stored form — stored CSL data keeps
  full given names, so Zenodo/CFF metadata stay complete.

## 6. Conventions

- Docs and comments in English; filenames kebab-case under `docs/`;
  figures as `images/fig{N}_{semantic-name}.pdf` matching the
  `\includegraphics` names; one semantic subfolder per concern
  (`src/`, `tests/`, `scripts/`, `images/`, `docs/`, `lean/`).
- Commits follow semver conventional-commit style, English subject lines,
  e.g. `docs(citations): add pipeline best-practices guide`,
  `fix(citations): correct Shou2023 author list and publication year`,
  `feat(pipeline): adopt biblatex bibliography from CSL`.
- Never push without an explicit instruction from the author.

## 7. Settled style decisions

- URL duplication with DOI in the rendered bibliography: **suppressed** via
  the `\AtEveryBibitem` hook (see §5); stored metadata keeps both. Applied
  identically to all five repositories.
- Reference ordering: **alphabetical** (`sorting=nyt`) per AMS convention;
  rendered author names: **initials** (`giveninits=true`).

## 8. Witnesses (tiers)

The manuscript marks the status of each claim inline, with an unbreakable
tag set in footnotesize and in its own colour. This section is the contract
of that device, written down here for whoever writes or edits the text.
The justification of the device — why a mark of this kind belongs in a
paper of pure mathematics, and what it does not claim — is argued in
`docs/witness-contract.md`; this section states only the contract. The
concrete instances of the rules below — site inventories, sentence tails,
applied states and verdict tables — live in `docs/reports/`.

### 8.1 Grammar — one macro, one optional argument

```latex
\tier{X}            -> [X]   the witness lives in the prose of the SAME
                             sentence (a \testref, the name of one of our
                             Lean declarations, an \eqref/\ref or a
                             \witness)
\tier[ids]{X}       -> X[ids] the optional argument carries INTERNAL ids
                             only: a \testref, or the raw names of
                             declarations of our own Lean file — written
                             with no macro around them, several of them
                             separated by ',' — printed in tt inside the
                             tag's own brackets.  An external source is
                             never a key of the tag — it is a real \cite
                             set next to the tag ([N]~\cite{key},
                             [P] in~\cite{key}), so a tag never prints a
                             number in its bracket
\witness{X}{a,b}    -> a block of its own, flush right, with the names
\wtag{L}{text}      -> the label of a witness list, where the
                             manuscript has one
```

The optional argument means **internal ids and nothing else**.  An id is
a `\testref` or the raw name of a declaration of the
repository's Lean file — the two are told apart in the preamble by the
token they contain (`\testref`, or an `\_` / a `,`, which only a name list
has).  Whatever else is written there — a `\cite` key, a plain alnum token
— is an error, not a fallback: the preamble raises `\PackageError` instead
of rendering a bracket full of a key.  The render of a legal tag is
therefore always the same shape: **the tag first, its ids inside the
brackets** —
`P[name1, name2]`, `N[test_x]`.  The ids never precede the tag either, so a
test witnessed in prose appears as `\tier{N} (\testref{test_x})`, never as
`(\testref{test_x}) \tier{N}`.

External sources stay outside the tag: the claim keeps its `\cite` next to
it, in the standard form `[P] in~\cite{key}` for a result proved in a
source and `[N]~\cite{key}` for a value quoted from one.  Two bracket
groups in a row (`[P] in [12]`) are then the tag's own bracket plus the
citation's, each printed by its own macro — and a tag alone never carries a
number.

**There is no `\Lean{}` (nor any per-repository variant of it) any
more.**  They were the artefact of the previous convention: a name printed in tt brackets of its
own, standing next to the tag of the same claim (`P[…]` beside
`N[test_x]`), which is the duplication this standard replaced.  Every
internal name now lives **inside** the tag — `\tier[name1, name2]{P}` — or
inside a `\witness{}` block, and an external name (a theorem of a sibling
repository) is never printed at all: the claim keeps its citation,
`in~\cite{key}`.

### 8.2 Rules for whoever writes or edits the text

1. **One claim, one tag.** No two tags are ever adjacent — `\tier{P}
   \tier{N}` is a bug, not a summary.
2. **An external source is the citation, not a tag — and never the key of
   one.** The source of a claim is its `\cite`, set immediately after the
   claim it supports: no tag says "this is cited", because the bracket of
   the citation already says it, and in numeric style a repeat carries its
   number like any other reference. What a tag carries is an *internal*
   witness, by identifier: a Lean name inside its brackets,
   `\witness{}` or `\testref{}` (the external forms are stated once, in
   §8.1: `[N]~\cite{key}`, `[P] in~\cite{key}`). `\tier[key]{X}` does not
   exist — the optional argument of `\tier` holds internal ids only and the
   preamble errors on anything else.
3. **A bare tag needs a witness in its sentence.** If the sentence has none,
   add the most honest one (the `\testref{}` of the test that checks the
   number, the Lean declaration that proves it — written inside the tag, so
   the tag is bare no longer — or an `\eqref`/`\ref`); never invent a
   citation.
4. **Every `\tier{N}` carries a `\testref{}`** when a test verifies it —
   either folded into the tag, `\tier[\testref{test\_x}]{N}`, or, when the
   sentence already carries other witnesses, as `\testref{}` in the prose of
   that same sentence, after the tag. The set of cited tests is pinned by
   the census test of the repository, so a new witness is added there too,
   after checking the test really recomputes the number next to it.
5. **`\tier{P}` without a bracket** means proved here, with no theorem name
   quoted at that point; the name, when it is quoted, goes into the tag
   itself (`\tier[name]{P}`) or, when the claim carries two ids or more and
   closes its sentence, into a `\witness{}` block — the criterion of §8.5
   (four gates and two labelled heuristics) decides which of the two.
   Proved in an external source is not "here": that is `[P] in~\cite{key}`,
   one bracket for the tag and one for the citation, each printed by its own
   macro.
6. **The gloss** (the *Evidence tags* paragraph, before the first mark of
   the body) defines the classes and nothing else — one sentence each. It
   is exempt from rule 3 — it defines, it does not claim — and it never
   mentions `P*`.
7. **`P*` is available; the released text uses `P`.** The class is fully
   functional in the preamble — the dispatch `\@namedef{tiercol@P*}` and the
   ochre `tierPs` colour — so `\tier{P*}` renders `[P*]` exactly like any
   other class, and it is there for intermediate commits between builds (an
   agent without Lean, in draft) that need to tag a claim as written but not
   yet named. The printed text never invokes it: the body marks those claims
   `P`, the gloss does not mention it and the prose no longer speaks of it.
8. **No status tags in captions.** A caption already names the test that
   generates the figure (`\testref{…}` of that test, and the test of the
   claim itself), which carries the status; a `\tier{…}`
   inside `\caption{…}` is removed, not kept. Tags belong to the body.

### 8.3 Alphabet

| Tag | Meaning |
|---|---|
| `\tier{P}` | proved and verified by machine (Lean) |
| `\tier{N}` | verified numerically, with the name of the test that checks it |
| `\tier[ids]{N}` | an `N` whose witness is a named test: `ids` is a `\testref` (several, separated by `,`), printed as `N[ids]` in tt by `\tier` itself |
| `\tier[names]{P}` | a `P` whose witness is the Lean declaration that proves it: `names` are written raw (no macro), printed as `P[name1, name2]` in tt by `\tier` itself — the form every migrated `\Lean{}` name now takes |
| `[N]~\cite{key}` | an `N` read off an external source: the citation sits next to the tag, never inside it |
| `[P] in~\cite{key}` | a `P` proved in an external source: one bracket for the tag, one for the citation |
| `\tier{P*}` | internal: renders `[P*]` in ochre, available between builds; the released text never uses it (rule 7) |
| `\witness{X}{ids}` | the ids of the claim, on a line of its own, flush right — `P[name1, name2]` or `N[test_a, test_b]` |
| `\wtag{L}{text}` | the label of a witness list, where the manuscript has one |

**Why there is no `L`.** A witness stresses that there *is* a reference, and
`P` and `N` earn their compactness by referencing by identifier — a theorem
name, a test name — while `L` only encodes "is cited", which the citation
itself already expresses and which costs a bracket more than it saves.

**Why there is no `R`.** `R` marked the direction of a reading rather than
how a claim is established; its sites repeated what the prose already
said, and a reading is now written as prose (`a reading of the
records, not a result about them`), so the class carried no information the
sentence does not.

### 8.4 Conventions of the device

- **Inline status is a convention of this project.** Each claim carries, next
  to it, how it was established — proved by machine, or computed and checked
  against a named test or an external source. That is a
  decision of this project and not an AMS or Chicago one; the real precedents
  are blueprints with a status per statement (`leanblueprint`), status tables
  status tables and artefact seals (argued in `docs/witness-contract.md`). The gloss at
  the first mark therefore states the classes and nothing else: the notes
  that explain the device belong to this standard, not to the page that
  carries the claim.
- **Colour is redundant with the letter** (WCAG 1.4.1): a tag reads the same
  in greyscale, so the letter alone always carries the meaning.

### 8.5 Inline or a line of its own — the criterion

The **shape** of a mark is decided by its ids, never by its class.  `P` and
`N` both appear inline and on a line of its own, so the shape tells a
reader how many witnesses a claim carries and where they sit, not what
kind of evidence it is; reading the shape as "the proof is a block, the
test is inline" was the drift this rule closes.

The criterion is **quantitative**: five quantities read off `main.tex`
with no judgement call, four gates, two labelled heuristics, one reading
pass to review it.

**The rule in one sentence.**  A claim whose id list carries **two ids or
more and 35 characters or more** goes on a line of its own
`\witness{X}{ids}` **only if the mark closes its sentence, does not close
a list item, and stands at least 75 words from the nearest block of its
paragraph**; every other site stays inline `\tier[ids]{X}`.  Two labelled
**heuristics** amend the cost and position conditions (gates 2 and 4): `u`
takes the verdict from the list the mark sits in, `p` prefers a line of its
own at a paragraph close — both stated below.  Gates 1 and 3 (`k ≥ 2`,
`r = 0`) are absolute: no heuristic lifts them.

#### The quantities

| Symbol | Quantity | How to measure |
|---|---|---|
| `k` | ids of the claim | count of `,` + 1 in the optional argument of `\tier`, resp. in the second argument of `\witness` |
| `L` | length of the id list, in characters | that argument with `\_` unescaped to `_`, `\testref{…}` reduced to its name, braces dropped |
| `r` | **sentence residual** — words of the *same sentence* that follow the mark | words between the mark and the next `.`, `!` or `?`, math and macros not counted; `r = 0` means the mark is the last element of its sentence |
| `d` | distance in words to the nearest `\witness` block of the same paragraph | paragraphs are blank-line separated; `—` when the paragraph has no block |
| `i` | 1 if the mark closes a `\item` of an enumeration, 0 otherwise | the last `\item`/`\item[` before the mark opens the item the mark ends |

#### The four gates

A claim with `k ≥ 2` is set as a block **iff all four hold**, unless one of
the heuristics below decides otherwise:

1. **`k ≥ 2`.**  One id never earns a line of its own: a single
   identifier fits in the bracket of the sentence it marks (calibration:
   the criterion-sites report in `docs/reports/`).
2. **`L ≥ 35`.**  Below 35 characters the flush-right line costs a
   paragraph break and buys no room: the bracket fits in the sentence
   (calibration: the criterion-sites report in `docs/reports/`).
3. **`r = 0`.**  `\witness` issues `\par … \par` (preamble), so it always
   ends the paragraph where it sits and the text after it opens a new one.
   Any residual — a trailing clause (`; …`, `, so …`, `which …`), a
   parenthetical (`(Figure~\ref{fig:background}(a))`), a closing
   `\testref` — would be stranded at the head of a new paragraph, and the
   sentence it belongs to would be torn in two.  **`r ≥ 1` ⇒ inline, no
   exception.**  The residual is counted, not estimated: a residual of a
   few words is a reference parenthetical or a closing `\testref` — a part
   of the sentence it follows, not a sentence of its own.
4. **`i = 0` and `d ≥ 75`.**  A block inside an enumeration would close
   the item's paragraph and set the mark off from the rest of the list;
   no block of the manuscript sits inside one.  And a second block a few
   lines below the first is monotone prose: 75 words is the tightest
   block-to-block distance the manuscript already accepts (calibration:
   the criterion-sites report in `docs/reports/`), so `d < 75` keeps the
   claim inline.

The four gates read as a paragraph, but they are each a number: the
criterion is reproducible by anyone who opens `main.tex`, and the applied
inventory it reproduces — every block, every flagged site, every counter —
is recorded in `docs/reports/` (the criterion-sites report of this
repository).

#### The two heuristics — `u` and `p`

Both are **heuristics**, labelled as such wherever they are applied: they
act only on the cost and position conditions of gates 2 and 4, never on
gates 1 and 3.  Each is a measurable positional signal, not a quantity of
the criterion.

**`u` — uniformity of a newline-separated list (HEURISTIC).**  In a list
whose elements already sit on their own lines — an `enumerate`, `itemize`
or `description` whose `\item`s each begin a line, and the numbered
sequence of `imported` statements — every mark of the run takes the same
form: all inline or all on a line of its own, never mixed.  The verdict is
therefore taken **from the run, not from the item**: census the other
marks of the run (inline `\tier` vs `\witness` block), then

- run all inline → the mark stays inline, whatever gates 2 and 4 would say;
- run all own-line → the mark goes on a line of its own, whatever gate 4's
  `i` would say;
- run mixed → `u` gives no verdict (it abstains), the run is recorded as a
  uniformity defect for a later harmonising pass, and the site falls
  through to `p` and to the four gates;
- run with no other mark → `u` abstains for lack of a census.

Measurable: the run is delimited by `\begin{…}`/`\end{…}`; the census
counts `\tier` and `\witness` occurrences inside it, excluding the mark
under review.

Best practice: visual rhythm — a list whose marks change shape from item
to item forces the eye to re-acquire the pattern, while a consistent form
keeps the list scannable
([How Users Read on the Web](https://www.nngroup.com/articles/how-users-read-on-the-web/)).

**`p` — paragraph close (HEURISTIC).**  A mark that is the last element of
its paragraph — only punctuation and commands follow it before the break —
adds a preference for a line of its own: the paragraph break the block
would cost is already there, and no residual can be stranded.  The
condition is positional: it is read without reference to `k` or `L`, and it
acts on whichever of gates 2 and 4 would keep the mark inline.  Among
candidates (`k ≥ 2`, `r = 0`), `p = 1` therefore sets the mark on a line of
its own; `p = 0` leaves the four gates to decide.  Gate 1 stays absolute:
a single id never earns a line of its own, at a paragraph close or
anywhere else.

Measurable: from the mark to the end of its paragraph (blank line, the
close of the enclosing environment) there is no word — only punctuation
and commands.

Best practice: do not split what the reader is following — a sentence
closed at its paragraph close keeps its parts together, which is the
reading side of the same rule that `r = 0` enforces
([PlainLanguage.gov — Sentences](https://www.plainlanguage.gov/guidelines/sentences/)).

**Order of decision.**  1. gate 1 (`k ≥ 2`), 2. gate 3 (`r = 0`) — both
absolute; 3. `u`, when it gives a verdict; 4. `p`; 5. gates 2 and 4
(`L ≥ 35`, `i = 0`, `d ≥ 75`).  A mark goes on a line of its own only when
one of steps 3–5 sets it there; otherwise it stays inline.  The verdicts
for the current manuscript — every candidate site by the tail of its
sentence, with its `u`/`p` values and the counter delta — are recorded in
`docs/reports/` (the `u`/`p` verdicts report of this repository).

#### How the criterion is reviewed

One reading pass over the site table of the criterion-sites report in
`docs/reports/` — it prints, for every
flagged site, the tail of the sentence the mark closes, so the whole check
is one question per row: *does any word of that sentence follow the mark?*
The same pass is what confirms gates 4 (`i`, `d`) and the census of `u` for
a new site, since all three are read from the lines around it.  No style
test is written for this: a CI check that re-derives what this section
already guarantees would test the document against itself; the census
test guards what the build depends on — the
test references the manuscript cites — and nothing here does.

#### Concrete material of this rule

The site table with the sentence tails, the calibration facts behind the
thresholds, the applied state of the last harmonising pass, and the
pending `u`/`p` verdict table all live in `docs/reports/` of the
repository that applies the rule — indexed by its
[`README.md`](reports/README.md). A report is a snapshot of one
repository state; the rule itself is this section.
